Recovering Homographies

Next, we need to establish a homography matrix so we can perform projective transformation on one image to bring it to the same angle of another. This homography matrix H essentially maps the pixels of an image to "matching" points in the other. We want to find the 3x3 matrix H with 8 degrees of freedom such that:
p' = Hp
Where p is the original point, and p' is the transformed point. Since we have 8 unknowns to solve for, we need at least 4 point correspondences between the two images. We can use these point correspondences to solve a system of equations containing the components of H. After rearranging some terms, this defined as the following:
System of Equations
We can use this to solve for a, b, c, d, e, f, g (h=1). This solution is homogenous and can be solved with least squares if we have more than 4 points. In fact, having more than 4 point correspondences is better because we get a more accurate computation for H.

Warping Images

Now that we have a way to compute the transformation matrix H between two images, we can warp each image towards its reference/original image. To avoid holes in the output image, I used inverse warping to warp each pixel.
To decide pixel values for each of the warped pixels, I implemented two different interpolation methods:
  • Nearest Neighbor Interpolation: Round coordinates to the nearest pixel value
  • Bilinear Interpolation: Use weighted average of four neighboring pixels
I tried out both methods of interpolation on the first image for each pair of images. Here are the comparisons:

Part B: Feature Matching for Autostitching

The goal of this part of the project was to create a system for automatically stitching images into a mosaic, without having to manually select point correspondences. I implemented code to detect features (corners), match them between images, and compute the homography using RANSAC.

Harris Corner Detection

To detect corners in images, I used the Harris Corner Detection algorithm. This algorithm works by looking at patches of pixels all over the image and looking for points with change in intensity in both the x and y directions, i.e. a "corner".
Here's what the result of that looks like:
Kitchen Harris Corners
That's a lot of corners! To reduce the number of corners, I applied Adaptive Non-Maximal Suppression (ANMS) to identify corners that are both "strong" and evenly distributed across the image.
Kitchen with ANMS-selected Corners

Feature Descriptor Extraction

Next, I extracted feature descriptors for each corner from the previous step, like so:
  • Blur the entire black-and-white image with a gaussian filter
  • For each point, take a 40x40 window around the point
  • Downsample the window to an 8x8 patch
  • Bias/gain normalize each patch with its mean and SD

Feature Matching

Now that we have all these feature descriptors, it's time to match the descriptors between images. That is, we need to find pairs of features that look similar and are thus likely to be good matches.
I did this by creating a K-NearestNeighbors model with the Euclidean distance metric to find the top 2 "matches" for each point in both images. Then, I applied Lowe's ratio test by using the ratio between the first and second nearest neighbors. Thresholding on this ratio gave a greater amount of correct mathces.
This worked decently well! Here's the results of the matches:

RANSAC for Robust Homography

The final step was to implement 4-point RANSAC (RANdom SAmple Consensus) to compute a robust homography matrix. Basically, I repeatedly sampled 4 random matches, computed the homography matrix using those correspondences, and then counted the number of "inliers", i.e. values within a threshold distance.
I ran this for a few thousand iterations, keeping track of the number of inliers and the best homography matrix seen so far. This produced some great matches! The red points are for "bad" matches, and the green points are for inliers.
