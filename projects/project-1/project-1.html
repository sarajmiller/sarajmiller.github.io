Project 1: Colorizing the Prokudin-Gorskii photo collection


Introduction

This project was inspired by the Russian photographer Sergei Mikhailovich Prokudin-Gorsky (1863-1944). Beginning in 1907, he traveled across the Russian Empire to take color photographs of everything he saw using red, green, and blue filters. He took the same photo 3 times, each time with a different filter.

By aligning each panel on top of each other, this creates a color image! In this project, I wrote code using several methods to align the panels on top of each other to create colored images.

Naïve Approach

My approach for aligning the R, G, and B panels was to fix one of the panels (say, the blue panel) and align the other panels on top of it. This naive approach produced the following on one of the example images:
cathedral.jpg
We can see colors now in the image, but it's easy to tell that the red, blue, and green panels are not aligned. Note that I cropped all the images before stacking them.

Better Approach

To align the R, G, and B panels, I fixed one of the panels (the blue one) and shifted the other panels around to align them on top of it. When shifting the panels, I used one of two metrics over a 30 x 30 pixel window to measure how "similar" two panels are on top of each other after shifting:
  • Euclidean distance (L2 Norm)
  • Normalized Cross Correlation (NCC)
Here are examples of how each metric performed for small images:
Euclidean distance
NCC
Using the Euclidean distance as a comparison tool performed marginally better than the naïve approach. Luckily, the NCC method performed great for this image!

Even Better: Pyramid Method

While the previous method worked for the smaller jpg images, this method didn't work for the larger images due to the window for comparison being too small.
We could increase the size of the window, but that would become expensive. Instead, we can use the image pyramid method:
  • Downsample the image by 1/2, up to a desired amount of times (I chose 5)
  • For the smallest sample, run an exhaustive search over your [-15, 15] window
  • Move up a level and double the shift to account for the change in size
  • Run the exhaustive search again over the same size window
  • Once you've reached the highest level, apply the shift to the corresponding color panel and re-align
This worked great on most of the large images!
lugano.tif after image pyramid

Final Approach: Edge Detection

One of the images, specifically the last one (Emir), didn't align properly. As a human, how would one manually align these images? Probably by aligning the edges in each panel together.
A better method is to use edge detection to align the images by their edges. OpenCV has a method called Canny for edge detection. Calling this method on each panel before shifting them produces the following image:
Aligning after edge detection
These edges look good! The pyramid method ran a lot quicker too. Here's the final image, as well as the dimensions I shifted by (height, width):
Red shift: (107, 40)
Green shift: (49, 24)
Looks great! If I went through all of my example images again using the edge detector to compare panels, I'd probably end up with more accurate images and a faster algorithm. But the example images look great already, so I let them be. I hope you enjoyed this project!
